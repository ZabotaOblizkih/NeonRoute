# Agentrules.md
# Стандарты разработки и правила для AI-агентов в проекте NeonRoute

> **Статус**: Обязательно к неукоснительному соблюдению  
> **Целевая кодовая база**: NeonRoute v0.9.0-beta (`C:\NeonRoute`)  
> **Язык разработки**: Python 3.10+ / PyQt6 (64-bit Windows)

---

## 1. Базовые архитектурные правила и технологические запреты

### 1.1. Запреты на библиотеки и биндинги
- **СТРОГО PyQt6**: Использование `PySide6`, `PyQt5` или `Tkinter` в основном интерфейсе категорически запрещено. Смешивание биндингов приводит к падению интерпретатора CPython при инициализации C++ указателей.
- **СТРОГО CPU для вспомогательных сервисов**: Библиотеки `fastembed`, `lancedb`, `f5-tts`, `soundfile` обязаны инициализироваться строго на CPU (`device="cpu"`). Запрещено передавать CUDA-тензоры в фоновые службы.
- **Никаких синхронных сетевых вызовов в GUI**: Запрещено вызывать `requests.get()`, `requests.post()`, `socket.create_connection()` или `subprocess.run()` внутри методов главного потока `MainWindow`, обработчиков кнопок или `paintEvent`. Любая блокировка очереди событий Qt дольше 35 мс считается критическим дефектом.

### 1.2. Кодировка и целостность файловой системы
- **Строго UTF-8 без BOM**: Все файлы (`.py`, `.json`, `.md`, `.qss`) обязаны читаться и записываться с явным указанием `encoding="utf-8"` без сигнатуры BOM (`\xef\xbb\xbf`).
- **Защита от блокировок Windows (WinError 32 / PermissionError)**: При сохранении данных категорически запрещено писать напрямую в рабочий файл. Все операции сохранения обязаны использовать функцию `atomic_write_json(target_path, data)`:
  1. Запись во временный файл `target.name.<uuid>.tmp`.
  2. Принудительный сброс файлового дескриптора на диск: `f.flush()` и `os.fsync(f.fileno())`.
  3. Атомарное замещение через `os.replace` с экспоненциальной задержкой до 5 попыток при перехвате `PermissionError`.

## 2. Организация многопоточности и очередей задач

### 2.1. Использование TaskQueueWorker
Любая задача инференса оборачивается в датакласс `InferenceTask` и отправляется в `task_queue.enqueue(task)`. Очередь работает в режиме `max_workers = 1`.

Приоритеты задач зафиксированы:
- `PRIORITY_HIGH = 0`: Интерактивные ответы языковой модели пользователю (LLM диалог).
- `PRIORITY_NORMAL = 10`: Генерация артов через Forge txt2img, озвучка F5-TTS, генерация документов.
- `PRIORITY_LOW = 20`: Фоновые сервисные задачи (экстракция памяти LanceDB, фоновый анализ каста сцены).

### 2.2. Прерывание задач (Cancellation Protocol)
Каждая фоновая задача обязана поддерживать:
- Потокобезопасный флаг прерывания `task.is_aborted.is_set()`.
- Регистрацию функции аппаратного прерывания `abort_fn`:
  - Для LLM: `lm_client.abort()` (закрытие сокета чтения чанков SSE).
  - Для Forge: `forge_client.interrupt()` (POST-запрос на `/sdapi/v1/interrupt`).
  - Для песочницы: завершение дочернего процесса `proc.kill()`.

## 3. Регламент безопасной модификации кода (Code Engine)

При автоматической модификации кода субагентом «Инженер» действуют следующие правила:

1. **Сжатие контекста (`ASTSkeletonizer`)**: Если файл превышает 350 строк, агент не читает его целиком, а получает архитектурный скелет: импорты, имена классов, декораторы, аннотации типов и сигнатуры методов с телом `...`.
2. **Точечные патчи (`PatchApplier`)**:
   Для правки существующих файлов отдавать предпочтение блокам `SEARCH/REPLACE`:
   ```
   <<<<<<< SEARCH
   def calculate_total(items):
       return sum(i.price for i in items)
   =======
   def calculate_total(items: list[Item]) -> float:
       return round(sum(i.price for i in items), 2)
   >>>>>>> REPLACE
   ```
   Патчер обязан применять алгоритм Fuzzy Matching (допуск различий в отступах и кавычках).
3. **Статический линтинг перед запуском (`CodeValidator`)**:
   Перед записью файла на диск выполняется валидация:
   - Проверка синтаксиса через `ast.parse()`.
   - **Scope Guard**: поиск необъявленных переменных (`NameError`) через таблицу символов `symtable`.
   - **Anti-Truncation Guard**: отслеживание маркеров лени модели (`# rest of code`, `# TODO: implement`). Если файл сжался более чем на 75%, генерация бракуется.
   - **Спецификаторы библиотек**: запрет обращения к `.formula` у ячеек `openpyxl` (строго `.value = '=SUM(...)'`). Запрет вызова `.font` и `.fill` у ячеек `python-docx` (строго через `paragraphs[0].runs`).
4. **Git-песочница (`GitSandboxManager`)**:
   Перед началом хода в папке `workspace/projects/<id>/` создается чекпоинт Git. При падении рантайма выполняется мгновенный откат: `git reset --hard HEAD` и `git clean -fd`.

## 4. Регламент рендеринга и графического интерфейса

1. **Glassmorphism и прозрачность**:
   Для корректного просвечивания обоев чата через `ChatBackgroundViewport` компоненты скролла обязаны иметь флаги:
   ```python
   widget.setAttribute(Qt.WidgetAttribute.WA_TranslucentBackground, True)
   widget.setAutoFillBackground(False)
   ```
2. **Запрет масштабирования в `paintEvent`**:
   Категорически запрещено вызывать `pixmap.scaled()` внутри метода `paintEvent()`. Масштабирование выполняется строго внутри `resizeEvent()` с сохранением результата в буфер `self._scaled_pixmap`.
3. **Плавный стриминг текста (28 FPS)**:
   Прием потоковых чанков от модели накапливается в буфер `_stream_token_buffer`. Сброс на экран выполняется по таймеру с интервалом 35 мс (`QTimer`, 28 кадров в секунду), предотвращая мерцание и блокировку очереди GUI при высокой скорости генерации токенов (60+ tok/s).

## 5. Процедура завершения работы (Graceful Shutdown)

При получении события `closeEvent` в `MainWindow`:
1. Запрещено выполнять синхронную выгрузку прямо в теле `closeEvent`.
2. Событие перехватывается: `event.ignore()`, окно скрывается (`self.hide()`), отображается модальный `ShutdownProgressDialog`.
3. Вся процедура выгрузки передается в `ShutdownWorker(QThread)`.
4. Внутри `ShutdownWorker` первым шагом запускается аварийный `Watchdog` на 8.0 секунд (`os._exit(0)`).
5. Порядок завершения процессов:
   - Шаг 1: Приоритетное завершение дерева процессов SD Forge через `taskkill /F /T /PID` (timeout=3s).
   - Шаг 2: Зачистка оторванных процессов Forge (`launch.py` / `webui`) через `psutil`.
   - Шаг 3: Выгрузка моделей LM Studio через REST `/api/v0/models/unload` и CLI `lms unload --all` (timeout=5s).
   - Шаг 4: Оптимизация и компактизация LanceDB (`memory_db.close()`).
